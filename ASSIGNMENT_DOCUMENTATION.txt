PART 1: PUSHING DOCKER IMAGE TO DOCKER HUB
================================================================================

SYSTEM OVERVIEW:
----------------
Project: Student Performance Prediction ML System
Technology Stack: Flask REST API, Machine Learning (Random Forest), Docker
Docker Image Base: Python 3.9-slim
Application Port: 5000

STEPS PERFORMED:
----------------

Step 1: Build Docker Image Locally
-----------------------------------
Command Used:
    docker build -t student-performance-api .

Explanation: This command builds a Docker image from the Dockerfile in the 
current directory. The image contains the Flask API, trained ML models, and 
all dependencies needed to predict student performance.

   WHAT TO CAPTURE: Terminal showing the docker build command execution
   HIGHLIGHT:

Step 2: Tag Image for Docker Hub
---------------------------------
Command Used:
    docker tag student-performance-api:latest YOUR_USERNAME/student-performance-api:latest
    docker tag student-performance-api:latest YOUR_USERNAME/student-performance-api:v1.0

Explanation: Tagging creates references to the same image with different names.
We create two tags:
- "latest": Points to the most recent version
- "v1.0": Specific version number for tracking

📸 SCREENSHOT 2: Docker Images List
   WHAT TO CAPTURE: Output of "docker images" command
   HIGHLIGHT:

   - Image size and creation date


Step 3: Login to Docker Hub
----------------------------
Command Used:
    docker login

Explanation: Authenticates with Docker Hub using your username and password/token.
This is required before pushing images to Docker Hub registry.

Step 4: Push Image to Docker Hub
---------------------------------
Commands Used:
    docker push YOUR_USERNAME/student-performance-api:latest

Explanation: Uploads the Docker image to Docker Hub repository. Both tags are
pushed separately. The image layers are uploaded once and shared between tags.

PART 2: KUBERNETES DEPLOYMENT & SERVICE FILES

KUBERNETES CONFIGURATION OVERVIEW:
-----------------------------------
Application: Student Performance ML API
Replicas: 3 (for high availability)
Container Port: 5000
Service Type: LoadBalancer (for external access)
Resource Limits: CPU and Memory constraints configured

FILE 1: DEPLOYMENT YAML (deployment.yaml)
------------------------------------------
Purpose: Defines how the application should be deployed in Kubernetes cluster

Key Components:
- apiVersion: apps/v1 (Kubernetes Deployment API version)
- kind: Deployment (Resource type)
- metadata: Name and labels for the deployment
- spec: Deployment specification
  - replicas: 3 (Number of pod instances)
  - selector: How to identify pods managed by this deployment
  - template: Pod template specification
    - containers: Container configuration
      - image: Docker Hub image reference
      - ports: Container port 5000
      - resources: CPU and memory limits
      - livenessProbe: Health check endpoint
      - readinessProbe: Ready check endpoint

Important Features:
- Rolling update strategy for zero-downtime deployments
- Resource limits to prevent resource exhaustion
- Health checks to ensure pod reliability
- Labels for service discovery

📸 SCREENSHOT 6: deployment.yaml File Content
   WHAT TO CAPTURE: Text editor or cat command showing deployment.yaml
   HIGHLIGHT:
   - "kind: Deployment" line
   - "replicas: 3" line
   - "image: YOUR_USERNAME/student-performance-api:latest" line
   - Resource limits section
   - Liveness and readiness probe sections


FILE 2: SERVICE YAML (service.yaml)
------------------------------------
Purpose: Exposes the deployment to network traffic and provides load balancing

Key Components:
- apiVersion: v1 (Kubernetes Service API version)
- kind: Service (Resource type)
- metadata: Name and labels for the service
- spec: Service specification
  - type: LoadBalancer (Exposes service externally)
  - selector: Matches pods with specific labels
  - ports: Port mapping configuration
    - port: 80 (External access port)
    - targetPort: 5000 (Container port)
    - protocol: TCP

Important Features:
- LoadBalancer type provides external IP
- Port 80 mapped to container port 5000
- Selector matches deployment labels
- Enables load balancing across multiple replicas

📸 SCREENSHOT 7: service.yaml File Content
   WHAT TO CAPTURE: Text editor or cat command showing service.yaml
   HIGHLIGHT:
   - "kind: Service" line
   - "type: LoadBalancer" line
   - Port mapping (port: 80, targetPort: 5000)
   - Selector section matching deployment labels

================================================================================
TROUBLESHOOTING NOTES
================================================================================

If Docker Push Fails:
- Verify Docker Hub login: docker login
- Check image tag matches your username
- Ensure repository exists on Docker Hub

If Pods Don't Start:
- Check image pull: kubectl describe pod <pod-name>
- Verify image name in deployment.yaml
- Check Docker Hub image is public or add imagePullSecrets

If Service No External IP (Minikube):
- Use: minikube service student-performance-service --url
- Or: minikube tunnel (in separate terminal)

If Application Not Responding:
- Check pod logs: kubectl logs <pod-name>
- Verify container port matches service targetPort
- Test from within cluster: kubectl exec -it <pod> -- curl localhost:5000/health
